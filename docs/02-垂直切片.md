# 不对劲 · 垂直切片范围

> 本文只回答：这一刀切什么、不切什么、怎样才算切到。  
> 体验对错仍以 [00-体验目标.md](./00-体验目标.md) 为准。

---

## 1. 这一刀要验的一句话

没玩过的人打完这一局，能指着结算说：**「揭招牌是加班，揭收银是走账，我揭的是这个。」**

验不到这句话，切片失败。平台、广告 SDK、主题换皮都不在这一刀里。

## 2. 切进去的层

| 层 | 切到什么 | 本刀标准 |
|---|---|---|
| 规则 | 4 场现场、每场 ≥2 揭、≥1 陷阱、3 次告错、单场限时、案底分支 | 纯逻辑可单测；状态机无 leftover / remaining / lane / leak |
| 单局闭环 | 进现场 → 揭完四场 → 结算点名靠哪几处 → 再来 | 能赢能输能重开 |
| 十秒开场 | 0 秒就看见便利店和口气牌；第一次揭发生在 10 秒内 | 无菜单、无选关；两处能揭同时脉动 |
| 现场演出 | 揭完物件翻面，口气牌换句 | 手绘大色块现场，物件最短边 ≥ 88 |
| 案底教学 | 揭招牌走加班场，揭收银走走账场 | 同一局两条线可复现 |

## 3. 这一刀明确不切

| 层 | 为什么现在不切 |
|---|---|
| 抖音包 / Tap 包 / 真实广告 SDK | 微信包按 code_2 同一套 runtime 先接上 |
| 埋点上报 | 事件名按 01 节留下，切片只打 console |
| 局外进度 / 侦探图鉴 | 会抢走「揭」 |
| 像素级找茬、两图对照 | 反目标，永远不切 |
| 完整 2–4 分钟句库扩写 | 4 场够验密度与案底 |

## 4. 切片内容（锁死）

主题：便利店这一天。第一场带「两处都能揭」的手把手。

| 场 | 口气 | 能揭 | 陷阱 | 下一场 |
|---|---|---|---|---|
| 1 便利店夜班 | 今日休息 | 招牌 → 今日加班；袖口现金 → 他在走账 | 过期面包 | 揭招牌去「加班」；揭收银去「走账」 |
| 2a 谁让店加班 | 谁让店加班 | 排班表 → 自愿是假的；老板名牌 → 老板定的 | 加班费红包 | 饭局 |
| 2b 账对不上 | 账对不上 | 监控对着墙 → 有人拧歪了；抽屉夹层 → 走账还在 | 过期小票 | 饭局 |
| 3 这顿我请 | 这顿我请 | 账单塞给别人 → 他没请；手机 AA → 口头请实际 AA | 空酒杯 | 收工 |
| 4 今天到底怎么了 | 随案底变 | 改过的牌 → 今天是加班的故事；掉出来的钱 → 今天是走账的故事 | 路过的猫 | 结算 |

全局限 3 次告错。第一场 40 秒，其余约 32 秒。揭开进入下一场。  
界面必须让人看见：口气牌、至少两处能点的物件、揭完的新口气、案底。

## 5. 怎样才算切到（验收）

1. 问「刚才怎么赢的」，答案里有具体物件，且说得出「不是另一处」。
2. 两人打第一场，能走出加班线和走账线。
3. 前 10 秒盲测：不会被说成找茬、找不同、寻物、文字组对。
4. `npm run build` 通过（类型 + 测试 + 产物）。

4. 按 code_2 接上微信小游戏 runtime，产出 `build/wechat/`。
5. 能揭就停，不顺手加系统。
